# OJ CMS: граница starter и проекта

Цель пользователя: новый Payload-проект из OJ CMS сразу получает оригинальный интерфейс без повторной сборки админки или имитации её дизайна.

## Текущее состояние

Исходный `C:/Users/olegk/code/oj-cms` содержит Next-интерфейс и localStorage-демо, но не Payload backend. В КЭМЗ исходные компоненты и CSS перенесены в `src/oj`, demo provider заменён реальным REST adapter. Исходный репозиторий OJ пока не менялся.

## Что должно входить в общую базу

- Оригинальные shell, dashboard, коллекции, media, аккаунт, общие контролы и CSS без проектных стилистических переопределений.
- Payload config с users, серверными ролями, drafts/versions, безопасной авторизацией и подключаемыми PostgreSQL/S3.
- Registry коллекций, globals и полей: тип поля определяет оригинальный OJ-контрол; нет hardcode products/news КЭМЗ в общих компонентах.
- Полноценный Lexical editor с таблицами, отношениями, загрузками и проверкой совместимости сохранённого JSON.
- Настоящие сохранение/публикация, ошибки, загрузка файлов, версии и защита несохранённых изменений. Не имитировать доступные действия.
- Безопасное удаление медиа с проверкой связей на сервере, включая rich text и версии. Клиентская подсказка usedBy не является достаточной защитой.
- Секреты только в окружении, example-конфиг без данных/контактов КЭМЗ и без demo-содержимого в runtime.
- Проверка чистого развёртывания и сквозных сценариев в отдельном тестовом проекте.

## Что остаётся только в КЭМЗ

Коллекции каталога и документов, поля совместимости оборудования, миграция Contentful, подтверждённые факты завода, существующие SEO URL и публичный сайт.

## Порядок выделения

1. Завершить и проверить реальные сценарии текущей интеграции, сохранив дизайн OJ.
2. Перенести adapter и registry в исходный OJ репозиторий; demo оставить отдельным режимом, не основой production.
3. Собрать чистый проект из starter и проверить вход, роли, CRUD, media, drafts и публикацию.
4. Подключить КЭМЗ через проектную конфигурацию. Только после этого считать OJ готовой базой для следующих проектов.
