# Работа с сайтом КЭМЗ

## Назначение и границы изменений

Это существующий публичный сайт ОАО «Карпинский электромашиностроительный завод» (КЭМЗ). Работайте как с редизайном действующего Nuxt-приложения: меняйте представление и компоненты, но не заменяйте сайт вымышленными данными или новой архитектурой без необходимости.

- Компания находится в Карпинске, Свердловская область. Не путать с другими предприятиями КЭМЗ.
- Источник фактов, технических значений и допустимого копирайта: `docs/brand-facts.md`, текущий Contentful-контент, локальные документы и данные, уже присутствующие в репозитории.
- Не придумывайте характеристики, модели, совместимость оборудования, клиентов, регионы/страны поставок, сертификаты, даты, историю, контакты, сотрудников и документы. Нет подтверждённых данных: не показывайте утверждение, а проектируйте корректное пустое/необязательное состояние.
- Не используйте lorem ipsum и не заменяйте реальные русскоязычные тексты англоязычными заглушками.

## Стек и архитектурные инварианты

- Nuxt 3, Vue Composition API и `<script setup>` для нового или изменяемого кода.
- Contentful подключён через `plugins/contentful.ts`. Для загрузки контента используйте `useAsyncData` и `$contentful.getEntries` со стабильными ключами; не меняйте контракты полей CMS ради вёрстки.
- Существующие общие элементы: `components/AppHeader.vue`, `components/AppFooter.vue`, формы `components/Form.vue` и `components/InputPhone.vue`. Серверная обработка заявок находится в `server/api/sendMail.post.ts`.
- Расширяйте текущую связку Tailwind и SCSS в `assets/css/`; не вводите второй параллельный дизайн-стек. Централизуйте токены, не разбрасывайте случайные цвета по компонентам.
- Не удаляйте и не переименовывайте работающие компоненты, данные, документы или функции, если нет совместимой миграции.

## Маршруты, данные и SEO

Сохраняйте URL, динамические параметры, маршруты и их назначение:

- `/`, `/about`, `/contacts`, `/documents`, `/legal`, `/news`, `/news/[new]`, `/products`, `/products/[category]`, `/products/[category]/[product]`, `/special`.
- Отдельный `/production` добавляйте только когда он действительно нужен и не конфликтует с навигацией или данными. Для него нужны корректные метаданные.
- У каждой публичной страницы остаются уникальные `title` и `description`; используйте `usePageSeo`/`useSeoMeta` и существующие JSON-LD-утилиты, где они применяются.
- Сохраняйте canonical, Open Graph, robots, sitemap и структурированные данные, если они уже есть. Не меняйте индексируемые URL ради нового дизайна.
- Изображения Contentful используют HTTPS, содержательные русские `alt` и ленивую загрузку ниже первого экрана. Не ухудшайте CLS и не добавляйте тяжёлую зависимость для небольшого визуального эффекта.

## Формы, безопасность и доступность

- Не обходите клиентскую и серверную валидацию заявок, honeypot, нормализацию российского телефона и rate limit. Секреты остаются только в `runtimeConfig`/переменных окружения.
- Используйте семантический HTML, один `h1` на страницу, последовательную иерархию заголовков, видимый фокус, доступные имена кнопок и ссылок. ARIA добавляйте только когда семантики HTML недостаточно.
- Mobile не является уменьшенным desktop: без ненужного горизонтального overflow, с touch-областями и читабельными таблицами характеристик.

## Визуальное направление

Полная спецификация: `docs/DESIGN_SYSTEM.md`. Для UI-работы применяйте навык `frontend-design` (Implement Designs), затем прочитайте `.cursor/skills/kemz-industrial-design/SKILL.md` и `docs/brand-facts.md`; для интерфейсного и маркетингового текста также `.cursor/skills/stop-slop/SKILL.md`.

- Стиль: industrial editorial + engineering catalog. Сине-белая айдентика, строгая инженерная сетка, реальные фото завода, карьерной техники и оборудования.
- Не делайте SaaS/стартап-интерфейс, glassmorphism, «card soup», кислотные/glow-эффекты, фиолетовые градиенты и декоративную анимацию.
- Референс из задачи задаёт композицию, плотность, контраст, типографику и отношение к фотографии. Это не инструкция копировать макет или подменять реальные данные.
- Новые растровые ассеты создавайте только при реальной нехватке подходящего фото. Предпочитайте встроенный Image Generation; сохраняйте выбранный файл в проекте, отмечайте его в `docs/brand-facts.md` и добавляйте русскоязычный `alt`.

## Обязательный порядок UI-работы

1. До правок изучите связанные route, компоненты, CSS, источники Contentful и SEO. При вопросах о кодовой базе сначала используйте `graphify query`, `graphify path` или `graphify explain`, если доступен `graphify-out/graph.json`.
2. Сформулируйте компактный план токенов, типографики, сетки и композиции по `docs/DESIGN_SYSTEM.md`; переиспользуйте реальные данные и ассеты.
3. Вносите изменения последовательно, без массового удаления: токены/глобальные стили, shell, затем ключевые страницы.
4. После завершения каждой ключевой страницы запустите приложение и визуально проверьте её в браузере в 1440×900, 1024×768 и 390×844. Снимите screenshots и оцените композицию, типографику, отступы, overflow, качество изображений и соответствие референсу. Явные UI-проблемы или более слабый результат исправляйте до перехода к следующей странице. Успешная компиляция сама по себе не означает готовность страницы.
5. После существенных правок кода выполните `graphify update .` (AST-only).

## Проверка перед передачей

Выполните релевантные проверки и сообщите результаты:

```powershell
npm run lint
npx nuxi typecheck
npm run build
```

Если проверка не запускается из-за существующей конфигурации или окружения, не маскируйте это: сообщите команду и фактическую причину. Не создавайте коммит и не выполняйте push без прямой просьбы пользователя.

## Git

- Базовая ветка интеграции: `develop`, production: `master`.
- Обычные изменения начинайте в отдельной ветке от `develop`; для этой задачи пользователь запросил ветку `dev-codex`.
- Не выполняйте force-push, интерактивный rebase или `--no-verify` для `master`/`develop`.
